# FeynLoop · 파인루프

PDF에서 학습 개념을 추출하고 **원문을 보지 않고 자신의 말로 설명**하는 한국어 파인만 학습 웹앱입니다.

## 실행

Node.js 22.13 이상 또는 24 이상이 필요합니다.

```sh
npm install
# 처음 설정할 때만 실행합니다. 기존 .env.local을 덮어쓰지 마세요.
cp .env.example .env.local
npm run dev
```

[로컬 앱](http://localhost:3000)을 엽니다. 기본 선택은 데모이며 비로그인 상태에서 예제 문서와 PDF 업로드로 학습 흐름을 체험할 수 있습니다.

### 실제 Gemini 학습 시작

1. PDF 등록 화면에서 Gemini·계정 저장 설정이 준비됐는지 확인합니다. 이 표시는 환경변수 존재 여부이며 실제 API 연결 성공을 의미하지 않습니다.
2. **실제 Gemini 학습**을 선택하고 아이디·비밀번호로 가입하거나 로그인합니다. 메일은 보내지 않습니다.
3. **새 PDF 업로드** 또는 **Gemini로 예제 분석하기**를 누릅니다. 이때 문서 분석 요청이 발생합니다.
4. 개념을 선택해 원문 없이 설명합니다. 설명·답변 제출 시 실제 Gemini 평가와 질문 생성 요청이 발생합니다.
5. 질문을 마치면 필요한 근거만 확인한 뒤 재설명하고 결과를 저장합니다.

페이지 열기, 설정 표시, 학습 방식 선택, 로그인 창 열기는 Gemini 요청을 발생시키지 않습니다. 데모를 선택하면 키와 로그인이 있어도 실제 AI를 호출하지 않습니다. 기존 데모 프로젝트의 모드는 바뀌지 않으므로 실제 모드로 새 프로젝트를 생성해야 합니다.

```sh
npm run typecheck
npm test
npm run build
npm start
```

## 학습 흐름

1. PDF 업로드 → 서버에서 검증·페이지별 텍스트 추출·개념 분석
2. 개념 선택 → 원문 없이 기억으로 첫 설명
3. 사용자 답변을 반영한 질문 3회 (질문마다 힌트 최대 2단계)
4. 필요한 경우 관련 근거만 확인 (최대 3페이지, 페이지별 최대 650자)
5. 근거를 닫고 처음부터 재설명
6. 첫 설명·최종 설명의 평가와 변화, 근거·힌트 사용 기록 확인

개념 이름·학습 목표는 학습 시작 전에만 편집할 수 있습니다. 변경 저장을 누르거나 설명을 시작할 때 편집 내용을 저장합니다. 설명·재설명 중에는 원문 열람 요청도 서버에서 거부합니다. 모바일·데스크톱 모두 하나의 채팅에서 진행합니다. 마지막 정리 때 문서 근거를 다시 숨깁니다.

## UI 구성

모바일 시안을 바탕으로 오프화이트 배경, 라임색 포인트, 둥근 카드와 하단 메뉴를 사용합니다. 학습실과 결과는 어두운 배경으로 구분합니다. 개념을 선택하면 모바일·데스크톱 모두 하나의 채팅방에서 첫 설명, 꼬리질문, 힌트, 마지막 정리까지 이어집니다. 별도 설명 에디터나 근거 확인 페이지로 이동하지 않습니다. 근거는 질문을 마친 뒤 채팅 안에서 선택적으로 펼쳐 보고 마지막 정리 때 다시 숨깁니다.

- 오늘: 저장된 카드에서 다음 설명과 이어할 카드를 선택
- 카드함: 문서·학습 상태·검색으로 카드 확인
- 카드 상세: 첫 설명·질문 답변·최종 재설명 기록 확인
- 등록: PDF 업로드와 실제 Gemini/데모 선택
- 카드 확인: 추출된 개념 이름·학습 목표 수정 및 저장
- 설명 세션: 원문 없는 설명·질문·힌트·근거 확인·재설명
- 결과·기록: 실제 완료 카드 수, 질문 수, 힌트·근거 열람 이력과 설명 비교

표시할 기록이 없으면 빈 상태를 보여주며 임의의 숙달도·과신 점수를 생성하지 않습니다. 카드 편집 내용은 개별 저장하거나 설명 시작 시 저장하고, 화면 이동과 질문 전환 때는 화면 상단으로 이동합니다.

## 서버 데이터와 접근 제어

브라우저에는 원문 전체를 보내지 않습니다. PDF 추출도 서버에서 수행합니다. 클라이언트가 원문이나 학습 단계를 임의로 제출해 평가를 조작할 수 없도록 기존 `/api/ai`는 410으로 차단했습니다.

- `feynloop_sources`: 페이지별 문서 원문. 서버 전용이며 사용자 공개 키·로그인 토큰으로 직접 읽을 수 없습니다.
- `feynloop_projects`: 개념·세션·평가·진행 버전·요청 처리 이력. 서버 전용입니다.
- 비공개 `pdfs` 버킷: 업로드 PDF 보관. 이전 버전의 사용자 직접 다운로드 정책을 회수합니다.
- 모든 계정 API는 Supabase에서 토큰을 검증한 뒤 **사용자 ID 조건으로** 조회·변경합니다. 서버 키를 사용하는 DB 클라이언트에 사용자 토큰을 섞지 않습니다.
- 공개 응답은 허용 필드만 구성합니다. 학습 도중에는 비공개 평가·정답 인용·아직 요청하지 않은 힌트를 보내지 않습니다. 최종 평가는 선택한 완료 세션에서만 제공합니다.
- `version`으로 동시 변경을 검사하고, 최근 요청 ID 30개를 기록해 같은 제출의 재전송이 학습 단계를 중복 진행하지 않도록 합니다. 충돌은 409로 반환합니다.
- 제출 실패 시 입력과 기존 단계가 유지됩니다. 설명은 **저장하고 잠시 쉬기** 또는 단계 제출 시 서버에 저장합니다. 저장하지 않은 입력은 새로고침하면 사라집니다.

이미 사용자에게 공개한 근거의 복사·기억이나 본인이 가진 PDF 파일 접근까지 차단하는 시험 감독 기능은 아닙니다. 근거 열람은 서버에 기록하며, 다음 단계 응답에서는 해당 발췌문을 제외합니다.

## 데모 모드

비로그인 사용자는 HttpOnly·SameSite 쿠키로 분리된 서버 데모 저장소를 사용합니다. 기본 경로는 `.feynloop-data/`이며 Git에서 제외됩니다. 브라우저 localStorage에 문서·세션을 저장하지 않습니다. 쿠키를 지우면 해당 데모 기록에 다시 접근할 수 없고, 쿠키는 30일간 유지됩니다. 로그인 기록과 데모 기록은 자동 합치지 않습니다.

데모 PDF 분석은 번호가 붙은 제목을 개념 후보로 선택합니다. 제목이 없으면 페이지별 중립적인 후보를 만들며, 후보 수는 5개 미만일 수 있습니다. 데모 질문은 직전 답변을 반영하는 템플릿입니다. **의미 기반 이해도를 판정하지 않으며, 확인된 이해·오류를 임의로 생성하지 않습니다.** 예제는 직접 작성한 개념 6개입니다.

서버 데모 저장소는 로컬 개발·단일 서버용입니다. 운영에서 쓰려면 영속 디스크의 `FEYNLOOP_DATA_DIR`을 설정해야 합니다. 서버리스나 여러 서버에서는 `ALLOW_DEMO=false`로 끄고 Supabase 계정 저장을 사용하세요. 데모 잠금은 파일 단위, 계정 저장은 DB 버전 조건으로 경쟁 변경을 방지합니다. 프로세스 강제 종료 후 데모 저장 폴더에 `.lock`이 남았다면 서버를 정지하고 해당 잠금 파일만 정리한 뒤 재시작하세요.

## Supabase DB 설정과 자체 로그인

1. 처음 설치라면 Supabase SQL Editor에서 `supabase/schema.sql`을 실행합니다. 기존 v2 사용자라면 이 단계는 생략합니다.
2. **`supabase/migrations/20261108_accounts.sql`을 한 번 실행합니다.** 자체 계정·세션·요청 제한·새 학습 기록 테이블과 서버 전용 함수를 만듭니다. 기존 이메일 계정과 학습 기록은 수정하지 않습니다.
3. 서버의 `NEXT_PUBLIC_SUPABASE_URL`(또는 `SUPABASE_URL`)과 `SUPABASE_SECRET_KEY`를 설정합니다. 공개 인증 키는 이전 계정의 기록을 가져올 때만 필요합니다.
4. 서버를 재시작하고 `npm run check:setup`으로 테이블·함수·비공개 버킷을 검사합니다.
5. 앱에서 아이디·비밀번호로 회원가입합니다. 발급된 **복구코드는 한 번만 표시하므로 본인만 볼 수 있는 곳에 보관**합니다. 메일·SMTP·이메일 인증·Redirect URLs 설정은 새 가입과 로그인에 사용하지 않습니다.

### 계정과 로그인 상태

아이디는 영문자로 시작하는 영문 소문자·숫자·밑줄 4~24자이며 대소문자를 구별하지 않습니다. 비밀번호는 8~128자입니다. 서버에서 salt를 다르게 생성하고 scrypt(N=32768,r=8,p=3)로 검증합니다. 브라우저 저장소에 비밀번호나 새 로그인 토큰을 저장하지 않습니다.

로그인 시 256비트 난수 세션 토큰을 발급합니다. DB에는 토큰의 SHA-256 해시만 저장하고 브라우저에는 HttpOnly·SameSite=Strict 쿠키를 설정합니다. 운영에서는 Secure를 적용합니다. 세션은 30일 뒤 만료되며 로그아웃 시 서버에서도 폐기합니다. 다른 탭의 로그인·로그아웃은 BroadcastChannel로 반영합니다.

비밀번호를 잊었을 때는 **아이디+가입 복구코드+새 비밀번호**로 재설정합니다. 복구코드는 DB에 해시로만 저장하며, 사용 후 새 코드로 교체하고 이전 세션을 모두 폐기합니다. 아이디와 비밀번호, 복구코드까지 잃으면 이메일이나 아이디만으로 계정을 복구하지 않습니다.

### 이전 이메일 계정의 기록

새 로그인과 기존 Supabase Auth 계정은 별개입니다. 새 아이디로 로그인한 뒤 계정 메뉴의 **이전 학습 기록 가져오기**를 누르면 이 브라우저에 남아 있는 이전 세션을 확인합니다. 서버가 기존 토큰으로 Supabase에 소유자를 확인한 경우에만 기록을 복사합니다. 이메일 일치나 임의의 사용자 ID로 연결하지 않습니다. 이전 기록은 보존되고 이후 두 계정의 변경은 동기화되지 않습니다. 이전 계정 하나는 새 계정 하나에만 연결할 수 있습니다. 이전 세션이 없거나 만료됐다면 자동 이관하지 않습니다.

### DB 접근과 요청 제한

새 테이블은 RLS를 활성화하고 public·anon·authenticated 권한을 회수합니다. 계정·세션·학습 기록은 서버의 service_role만 읽습니다. 새 학습 기록은 `feynloop_account_projects`와 `feynloop_account_sources`에 사용자별로 저장합니다.

요청 제한은 DB의 원자적 함수로 여러 서버에서 공유합니다. 아이디별 로그인·가입·복구 시도는 각각 15분당 8회, 네트워크별 가입은 20회·나머지 인증 요청은 100회로 제한합니다. Netlify에서는 플랫폼의 실제 클라이언트 IP 헤더를 사용합니다. 다른 프록시에서는 신뢰 가능한 X-Forwarded-For만 덮어쓰는 환경에 한해 `FEYNLOOP_TRUST_PROXY=true`를 설정합니다. 신뢰 가능한 IP를 알 수 없으면 네트워크 제한을 공유합니다. 제한 시 Retry-After를 반환하며 자동 재시도하지 않습니다.

만료된 `feynloop_sessions`와 오래된 `feynloop_auth_limits` 행의 주기적 정리는 운영 환경에서 별도로 예약해야 합니다. 앱이 만료된 세션을 유효한 로그인으로 사용하지는 않습니다. [비밀번호 저장 기준](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html), [세션 관리 기준](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html).

## 환경변수

| 변수 | 용도 |
| --- | --- |
| NEXT_PUBLIC_SUPABASE_URL | Supabase DB URL (서버 전용 SUPABASE_URL로 대체 가능) |
| NEXT_PUBLIC_SUPABASE_ANON_KEY (선택: 이전 기록 이관) | 브라우저용 Publishable key 또는 anon 키 |
| SUPABASE_SECRET_KEY | 서버 전용 Supabase Secret key 또는 service_role 키 |
| GEMINI_API_KEY | Google AI Studio에서 발급한 서버 전용 Gemini API 키 |
| GEMINI_MODEL | Gemini 모델 이름. 기본 gemini-3.1-flash-lite |
| ALLOW_DEMO | false이면 비로그인 API 사용 차단. 기본 허용 |
| FEYNLOOP_DATA_DIR | 데모 기록을 보관할 영속 디렉터리. 기본 .feynloop-data |

실제 AI는 사용자가 `live` 방식을 명시적으로 선택하고 로그인과 Gemini 키가 모두 준비됐을 때만 사용합니다. 설정이 빠지면 오류로 안내하며 데모로 자동 전환하지 않습니다. 세션을 만들 때의 AI/데모 모드를 저장하며, 실행 도중 실제 AI 설정이 사라지면 데모 평가로 바꾸지 않고 오류를 안내합니다. PDF 텍스트와 설명은 Google Gemini API로 전송됩니다.

### Gemini 연결 방법

1. [Google AI Studio](https://aistudio.google.com/apikey)에서 API 키를 만듭니다.
2. `.env.local`에 다음 값을 넣고 개발 서버를 재시작합니다. `.env.example`에는 실제 키를 넣지 마세요.

```env
GEMINI_API_KEY=발급받은_키
GEMINI_MODEL=gemini-3.1-flash-lite
```

기존 `LLM_API_KEY`, `LLM_BASE_URL`, `LLM_MODEL` 설정은 더 이상 읽지 않으며 OpenAI로 요청하지 않습니다. Gemini 키가 없으면 데모를 사용합니다. 이미 데모로 만든 프로젝트는 모드가 유지되므로 키 설정 및 로그인 후 새 프로젝트를 만들어 실제 AI를 확인하세요.

Google의 기본 `generateContent` REST API를 사용하고 시스템 지시·문서 입력을 분리합니다. JSON Schema를 요청에 포함하고 응답은 Zod로 다시 검증합니다. 생각 과정으로 표시된 응답은 제외하며, 안전 제한·빈 응답·길이 제한·잘못된 JSON·연결 시간 초과는 학습 상태를 변경하지 않고 오류로 안내합니다. 429는 사용 한도 안내로 반환하며 자동 재시도·다른 모델로의 자동 전환은 하지 않습니다.

기본 모델의 무료 등급과 데이터 사용 정책은 [공식 요금표](https://ai.google.dev/gemini-api/docs/pricing)에서 확인할 수 있습니다. 계정·모델별 한도는 AI Studio에서 확인해야 합니다. 앱 설정만으로 Google의 결제 등급을 강제할 수 없으므로 무료 사용을 원하면 API 프로젝트를 Free 등급으로 유지하세요. 무료 등급에 전송한 PDF·설명은 제품 개선에 사용될 수 있습니다. 개인정보가 없는 공개 자료로 먼저 테스트하세요.

AI는 확인된 이해, 명시적 개념 오류, 설명에서 빠진 요소(이해 여부 미확인), 미확인을 구분합니다. 문서 기반 판단에 페이지·인용문을 요구하고 인용문이 실제 원문에 존재하는지 검사합니다. 인용 일치가 의미적 평가의 정확도를 보장하지는 않습니다. 첫 설명과 최종 설명에 동일한 평가 규칙을 적용하고, 결과에는 변화와 근거·힌트 사용 여부를 함께 표시합니다.

## API

| 경로 | 동작 |
| --- | --- |
| GET /api/auth/session | 현재 아이디·로그인 상태 확인 |
| POST /api/auth/session | signup / login / recover / logout (HttpOnly 쿠키) |
| POST /api/auth/import-legacy | 새 로그인 세션과 검증된 이전 토큰으로 기록 가져오기 |
| GET /api/projects | 본문 없는 프로젝트·학습 기록 목록 |
| POST /api/projects | multipart의 file·mode 필드로 PDF 업로드 또는 {"sample":true,"mode":"demo" 또는 "live"} 예제 생성. mode 생략 시 demo |
| GET /api/projects/:id | 프로젝트 복원. conceptId 쿼리로 선택한 완료 세션의 결과 또는 검토 단계의 이미 요청한 근거 확인 |
| POST /api/projects/:id | start / draft / submit / hint / evidence / rewrite / restart / editConcept 명령 |

변경 명령에는 `conceptId`, `version`, UUID `requestId`가 필요합니다. `submit`·`draft`는 `text`, `evidence`는 `page`, `editConcept`는 `title`·`description`을 사용합니다. 상태와 문서 근거는 서버가 읽으며 클라이언트가 제출한 상태 덮어쓰기를 허용하지 않습니다.

## 브랜치 규칙

- `main`은 병합된 코드를 관리하는 기준 브랜치입니다. 작업은 별도 브랜치에서 진행하고 PR로 병합합니다.
- 브랜치 이름은 `<유형>/<영문-kebab-case-설명>` 형식으로 작성합니다. 도구 이름을 접두사로 사용하지 않습니다.
- 하나의 브랜치는 하나의 목적을 다룹니다. 이슈가 있다면 설명 앞에 번호를 붙일 수 있습니다 (예: `fix/42-pdf-upload-validation`).

| 유형 | 용도 | 예시 |
| --- | --- | --- |
| `feat` | 새 기능 | `feat/feynloop-mvp` |
| `fix` | 오류 수정 | `fix/session-resume` |
| `docs` | 문서 변경 | `docs/setup-guide` |
| `refactor` | 동작을 유지하는 코드 개선 | `refactor/study-state` |
| `test` | 테스트 추가·개선 | `test/pdf-validation` |
| `chore` | 의존성·도구·설정 관리 | `chore/update-dependencies` |

## 커밋 규칙

- 커밋 제목은 `<유형>(선택 범위): <변경 내용>` 형식으로 작성합니다. 유형은 위 표의 값을 사용하고, 제목은 한국어 또는 영어로 변경 내용을 구체적으로 적습니다.
- 제목은 가능한 72자 이내로 작성하고 끝에 마침표를 붙이지 않습니다.
- 하나의 커밋에는 하나의 목적에 해당하는 변경을 담습니다. 이유나 주의점이 필요하면 제목 다음에 빈 줄을 두고 본문에 작성합니다.
- 예시: `feat(study): 질문과 재설명 학습 흐름 구현`, `fix(pdf): 잘못된 PDF 파일 업로드 차단`, `docs: 환경변수 설정 방법 추가`.
- 비밀 키, `.env.local`, 사용자 PDF, 빌드 결과물과 `node_modules`는 커밋하지 않습니다. 환경변수 이름과 빈 예시는 `.env.example`에서 관리합니다.
- PR에는 변경 내용, 검증 결과, 추가 설정이나 남은 제한 사항을 적습니다. 코드 변경 시 `npm run typecheck`, `npm test`, `npm run build`를 확인하고, 실행하지 못한 검증은 PR에 명시합니다.

## 현재 범위와 운영 전 확인

스캔 PDF OCR, 음성, 복습 알림, 지식 그래프는 제외합니다. 문서 분석은 현재 동기 요청이며 백그라운드 작업·자동 재시도는 포함하지 않습니다. 장문 문서는 모델 컨텍스트 한도에 따라 실패할 수 있습니다. 공개 운영 전 사용자별 사용량·비용 한도, AI 요청의 분산 속도 제한, 문서·기록 삭제 및 보존 정책을 추가해야 합니다. 여러 서버에서 동시에 같은 AI 요청이 실행되면 버전 검사로 중복 저장은 막지만 중복 호출 비용까지 보장하지는 않습니다. Storage 정리 실패에 대비한 고아 파일 정리도 필요합니다.

실제 Supabase·Gemini 연결은 별도 인증 정보와 환경에서 검증해야 합니다. 이 작업은 로컬 구현이며 외부 배포는 하지 않습니다.

## 실제 서비스 연결 확인

환경변수를 설정하고 서버를 재시작한 뒤 `npm run check:setup`을 실행합니다. 자체 로그인 테이블·함수, 서버 전용 테이블, 프로젝트 생성 함수와 비공개 PDF 버킷을 읽기 전용으로 검사합니다. 키나 사용자 기록은 출력하지 않으며, 메일 발송·데이터 변경·Gemini 호출을 하지 않습니다. Gemini는 키의 존재만 확인하므로 실제 키 유효성·모델 사용 가능 여부·사용 한도는 첫 실제 요청에서 확인됩니다.

앱의 PDF 등록 화면에서 **실제 Gemini 학습**을 선택하고 아이디·비밀번호로 로그인한 뒤 PDF를 등록하세요. 선택한 방식은 현재 브라우저에 유지되지만, 기존 데모 프로젝트의 모드는 바뀌지 않습니다. 데모 대화는 실제 이해도를 평가하지 않습니다. 실제 모드를 이용하려면 PDF 등록 화면에서 학습 방식을 바꿔 새 PDF를 등록하세요. 학습 방식 선택만으로 AI 요청을 보내지는 않습니다.

작성 중 설명은 현재 탭의 임시 저장소에도 보관합니다. 새로고침 후 같은 카드의 학습을 이어가면 복구합니다. 계정·문서·개념·학습 회차·질문 단계를 구분하며, 제출이 성공한 초안은 지웁니다. 탭을 닫거나 브라우저 저장소가 제한되면 임시 복구를 보장하지 않으므로 다른 기기에서 이어가려면 채팅 하단의 **대화 저장**을 사용하세요. PDF 원문은 브라우저 임시 저장소에 보관하지 않습니다.

### 학습 잔디와 연속 학습일

설명·답변·최종 정리를 성공적으로 전송해 저장한 경우만 해당 프로젝트의 비공개 `activity`에 한국 시간 날짜별 횟수를 기록합니다. AI 실패, 초안 저장, 같은 요청 ID의 재전송은 중복 집계하지 않습니다. 계정의 프로젝트를 합산해 잔디·현재 연속 학습일·최장 연속 학습일을 계산합니다. 오늘 학습 전에는 어제까지의 연속 기록을 유지하고, 어제도 학습이 없으면 현재 연속 일수는 0입니다. 날짜 정보가 없는 이전 학습 기록은 임의로 복원하지 않습니다.

비밀번호 변경은 로그인 쿠키와 현재 비밀번호를 모두 확인합니다. 변경 시 다른 기존 세션은 폐기하고 현재 브라우저에 새 세션을 발급합니다. 가입 복구코드는 그대로 유지됩니다.

### 요청 대기 안내

PDF 분석 중에는 중앙 대기 창에 작업 내용과 경과 시간을 표시합니다. 30초가 지나면 응답 지연 안내로 바뀌며, 완료 시 창이 닫힙니다. 채팅 설명·답변 제출과 힌트 요청은 대화 안의 점 세 개 말풍선으로 대기 상태를 표시합니다. 제출한 메시지는 먼저 내 말풍선에 나타나고, 실패하면 입력창에 복원됩니다. 진행률은 추정해서 표시하지 않습니다.

- Gemini 요청은 60초, 저장소의 개별 연결은 20초, 브라우저의 전체 요청 대기는 180초로 제한합니다.
- 실패하면 이유를 안내하며 작성한 설명을 유지합니다. 요청을 자동 재전송하지 않습니다.
- 브라우저 대기가 끝나도 서버 저장이 완료됐을 수 있으므로 카드함·학습 기록을 확인한 뒤 재시도합니다.
- 서버 실행 환경도 긴 요청을 지원해야 합니다. 프로젝트 API의 `maxDuration`은 180초로 선언했으며 실제 한도는 호스팅 설정에 따릅니다.

PDF 개념 추출은 기본 5 ~ 10개를 추천하지만, 짧은 문서는 근거가 있는 1 ~ 4개도 허용합니다. Gemini에 보내는 응답 스키마는 구조와 필수 항목 위주로 단순화하고, 글자 수·개수·양수·근거 페이지 검증은 서버에서 수행합니다.

AI 평가의 근거 비교에서는 유니코드 NFC와 공백·줄바꿈 차이만 정규화합니다. 단어·숫자·문장부호가 달라지거나 근거 페이지가 틀리면 해당 판단을 확정하지 않습니다. 확인된 평가만 유지하고 나머지는 미확인으로 남기며, 미검증 평가에서 나온 개선 조언·변화 요약·질문·힌트 대신 판단 보류 안내와 중립적인 확인 질문을 사용합니다. 추가 AI 재요청 없이 학습을 이어갑니다.
