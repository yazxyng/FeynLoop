# FeynLoop · 파인루프
PDF를 읽고 자신의 말로 설명하며 이해의 빈틈을 점검하는 한국어 파인만 학습 웹앱 MVP입니다.

## 실행
Node.js 22 이상을 사용합니다.

```sh
npm install
cp .env.example .env.local
npm run dev
```

브라우저에서 http://localhost:3000 을 엽니다. API 키 없이 예제 문서로 전체 흐름을 체험하거나 PDF를 업로드할 수 있습니다.

```sh
npm run typecheck
npm test
npm run build
npm start
```

PDF worker는 `postinstall`에서 설치된 pdfjs-dist 버전과 맞춰 public 폴더에 복사됩니다.

## 구현 기능
- 반응형 대시보드, 프로젝트 검색, 진행률, 이전 학습 이어하기
- PDF 파일 확장자·서명·크기 검증, 페이지별 텍스트 추출 (20MB / 150페이지 / 25만 문자)
- 개념 추출, 근거 페이지, 중요도, 학습 순서, 개념 이름·설명 편집
- 원문 텍스트 / 설명 에디터 / AI 학생 3영역 학습실, 모바일 탭
- 첫 설명 → 질문 3회와 힌트 → 최종 재설명 → 결과 비교
- 확인한 이해 / 보완 요소 / 미확인 분류
- 데모 브라우저 저장, Supabase 로그인 시 사용자별 클라우드 저장

## 데모와 실제 AI의 차이
API 키가 없으면 **문서 문장에서 후보를 선택하는 데모 분석**을 사용합니다. 의미를 이해해 추출하는 AI가 아니며 후보 수가 5개 미만일 수도 있습니다. 후보를 개념 단위로 수정할 수 있습니다. 데모 질문은 직전 설명·답변 일부를 반영하는 템플릿입니다. 실제 정확도·이해 향상을 판정하지 않으며 확인된 이해 항목을 생성하지 않습니다. 예제에는 직접 작성한 학습 개념 6개가 있습니다.

## Supabase 설정
1. Supabase 프로젝트를 만들고 `supabase/schema.sql`을 SQL Editor에서 한 번 실행합니다.
2. `.env.local`의 `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`에 프로젝트 URL과 공개 anon 키를 넣습니다. **service_role 키는 사용하지 마세요.**
3. Authentication에서 이메일 로그인을 활성화하고 Site URL 및 Redirect URLs에 앱 주소를 등록합니다 (개발: `http://localhost:3000`). 배포 환경에서는 HTTPS 주소를 사용합니다.
4. 앱 왼쪽 아래 데모 학습자를 눌러 로그인 링크를 받습니다. 메일의 링크로 같은 브라우저에서 돌아옵니다.

`projects` 테이블은 auth.uid()와 user_id가 일치하는 데이터만 허용합니다. 비공개 `pdfs` 버킷은 사용자 UUID 폴더에만 접근할 수 있습니다. 프로젝트 JSON에는 추출 텍스트·개념·설명·질문 기록을 저장하며 PDF 파일은 Storage에 별도로 저장합니다. 학습실은 추출 텍스트를 표시하며 원본 PDF 렌더러는 포함하지 않습니다.

비로그인 기록은 해당 브라우저 localStorage에 남으며 계정 기록과 분리됩니다. 로그인 시 자동 이관하지 않습니다. 클라우드는 단계 제출과 명시적 저장, 개념 편집 완료 때 저장합니다. 입력 중 텍스트를 다른 기기에서 이어가려면 **저장하고 잠시 쉬기**를 누르세요. 브라우저 저장 용량 오류와 클라우드 저장 오류는 화면에 표시됩니다.

## LLM 연결
서버 환경변수:

| 변수 | 용도 |
| --- | --- |
| LLM_API_KEY | 서버 전용 API 키 (없으면 데모) |
| LLM_BASE_URL | Chat Completions 호환 API 주소, 기본 https://api.openai.com/v1 |
| LLM_MODEL | 모델 이름, 기본 gpt-4.1-mini. 제공자가 지원하는 모델로 변경 가능 |

실제 AI API 호출에는 유효한 Supabase 로그인 토큰이 필요합니다. 키는 클라이언트에 노출되지 않습니다. Zod로 요청과 모델 응답을 검증하며 개념의 근거 페이지가 문서에 존재하는지 확인합니다. PDF 및 답변은 선택한 LLM 제공자에게 전송됩니다. 설정 변경 후 개발 서버를 재시작하세요.

## 폴더
- `src/components/workspace.tsx`: 대시보드·개념·학습실·결과와 세션 상태
- `src/components/ui`: shadcn 방식의 재사용 버튼 (CVA, cn), `components.json`으로 확장 가능
- `src/lib`: 데이터 모델, PDF 추출, Supabase 클라이언트, 데모
- `src/app/api`: 서버 AI 처리와 모드 조회
- `supabase/schema.sql`: 테이블·비공개 버킷·RLS 정책
- `tests`: 데모 판정 경계와 문서 입력 검증

## 브랜치 규칙

- `main`은 병합된 코드를 관리하는 기준 브랜치입니다. 작업은 별도 브랜치에서 진행하고 PR로 병합합니다.
- 브랜치 이름은 `<유형>/<영문-kebab-case-설명>` 형식으로 작성합니다. 도구 이름을 접두사로 사용하지 않습니다.
- 하나의 브랜치는 하나의 목적을 다룹니다. 이슈가 있다면 설명 앞에 번호를 붙일 수 있습니다 (예: `fix/42-pdf-upload-validation`).

| 유형 | 용도 | 예시 |
| --- | --- | --- |
| `feat` | 새 기능 | `feat/feynloop-mvp` |
| `fix` | 오류 수정 | `fix/session-resume` |
| `docs` | 문서 변경 | `docs/setup-guide` |
| `refactor` | 동작을 유지하는 코드 개선 | `refactor/study-state` |
| `test` | 테스트 추가·개선 | `test/pdf-validation` |
| `chore` | 의존성·도구·설정 관리 | `chore/update-dependencies` |

## 커밋 규칙

- 커밋 제목은 `<유형>(선택 범위): <변경 내용>` 형식으로 작성합니다. 유형은 위 표의 값을 사용하고, 제목은 한국어 또는 영어로 변경 내용을 구체적으로 적습니다.
- 제목은 가능한 72자 이내로 작성하고 끝에 마침표를 붙이지 않습니다.
- 하나의 커밋에는 하나의 목적에 해당하는 변경을 담습니다. 이유나 주의점이 필요하면 제목 다음에 빈 줄을 두고 본문에 작성합니다.
- 예시: `feat(study): 질문과 재설명 학습 흐름 구현`, `fix(pdf): 잘못된 PDF 파일 업로드 차단`, `docs: 환경변수 설정 방법 추가`.
- 비밀 키, `.env.local`, 사용자 PDF, 빌드 결과물과 `node_modules`는 커밋하지 않습니다. 환경변수 이름과 빈 예시는 `.env.example`에서 관리합니다.
- PR에는 변경 내용, 검증 결과, 추가 설정이나 남은 제한 사항을 적습니다. 코드 변경 시 `npm run typecheck`, `npm test`, `npm run build`를 확인하고, 실행하지 못한 검증은 PR에 명시합니다.

## 현재 범위와 운영 전 확인
스캔 PDF OCR, 음성, 복습 알림, 지식 그래프는 제외합니다. 암호화되거나 추출할 수 없는 PDF는 오류를 안내합니다. AI 평가의 정확도는 보장되지 않으므로 원문 근거를 확인해야 합니다. 장문 문서는 모델의 컨텍스트 한도에 따라 거절될 수 있습니다. 상용 공개 배포 전 사용자별 AI 호출 쿼터, 분산 속도 제한, 보존·삭제 정책, 비용 모니터링을 추가하세요. PDF와 AI 결과를 원자적으로 저장하지 않으므로 저장 실패 후 Storage에 남은 파일은 관리 정책으로 정리해야 합니다. 이 작업은 저장소 로컬 구현이며 외부 배포는 하지 않습니다.
