# #14 배포 환경 가입·로그인 검증

대상 이슈: https://github.com/yazxyng/FeynLoop/issues/14

## 배포 환경 확인 결과

2026-11-10에 사용자가 확인해 준 `https://fenyloop.netlify.app`에서 검증했다. 처음 전달된 `feynloop.netlify.app`은 Netlify 사이트 미발견 404였으며, 실제 대상 도메인과 철자가 다르다.

실제 사용자 계정 대신 이번 검증에서만 만든 임시 계정 하나를 사용했다. 비밀번호·복구코드·쿠키는 로그나 문서에 기록하지 않았고 AI 호출 및 학습 자료 생성은 하지 않았다.

| 확인 항목 | 실제 응답 및 확인 결과 |
| --- | --- |
| 공개 설정·비로그인 세션 조회 | 200, 로그아웃 상태 |
| 잘못된 가입 입력 | 400, 아이디 규칙 안내 |
| 신규 가입 | 201, 사용자·복구코드·세션 쿠키 발급 |
| 가입 직후 세션 조회 | 200, 가입 계정과 일치 |
| 중복 아이디 | 409, 다른 아이디 사용 안내 |
| 잘못된 비밀번호 | 401, 아이디 또는 비밀번호 확인 안내 |
| 로그아웃 | 200, 쿠키 만료 및 기존 세션 무효화 |
| 재로그인 | 200, HttpOnly·Secure·SameSite=Strict 확인 |
| 복구코드로 비밀번호 재설정 | 200, 새 복구코드 발급 |
| 복구 전 세션·비밀번호 | 이전 세션 무효, 이전 비밀번호 로그인 401 |
| 새 비밀번호 로그인 | 200 |
| 이전 복구코드 재사용 | 401 |
| 로그인 요청 제한 | 429, Retry-After 제공 |

## 코드에서 재현한 별도 오류

서버가 가입을 성공 처리한 뒤 클라이언트가 `BroadcastChannel`을 생성하거나 메시지를 보내면서 예외가 발생하면, `accountRequest`가 성공 응답과 복구코드를 반환하지 못했다. 브라우저의 보조 알림 기능 실패가 가입 실패로 표시될 수 있는 경로다. `SecurityError`를 발생시키는 회귀 테스트로 수정 전 실패를 재현했다.

- 탭 알림 실패는 인증 성공을 취소하지 않도록 분리했다.
- 채널 전송 실패 시에도 채널을 정리한다.
- 로그인·복구 완료 및 로그아웃 시 현재 탭의 계정 상태는 명시적으로 다시 읽는다.
- 응답 본문 수신 중의 시간 초과도 입력을 유지하는 안내로 처리한다.
- 사용자·복구코드가 누락되거나 잘못된 성공 응답은 완료로 처리하지 않는다.

UI 배치와 서버의 요청 제한·비밀번호 저장·세션 정책은 변경하지 않았다.

## 검증의 범위와 남은 확인

배포 API의 HTTP 흐름은 검증 시점에 정상 동작했다. 원래 사용자가 겪은 오류가 위 브라우저 알림 문제 때문이라고 확정하지 않는다. 수정 코드는 별도 PR로 배포한 뒤, 문제가 발생했던 사용자 브라우저에서 다시 확인해야 한다. 이 문서만으로 이슈를 자동 종료하지 않는다.

검증에 생성한 계정은 UUID·아이디·생성 시각이 일치하고 학습 자료가 없는지 확인한 후 계정·세션·해당 계정의 요청 제한 행을 정리했다. 비밀 값을 담은 임시 파일도 삭제했다. 기존 사용자 데이터와 네트워크 공용 제한은 변경하지 않았다.
